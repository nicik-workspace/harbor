# [Bifrost](https://github.com/maximhq/bifrost)

> Polskie tłumaczenie dokumentacji. [Oryginał angielski](./2.3.84-Satellite-Bifrost.md) pozostaje źródłem prawdy.

> Uchwyt: `bifrost`<br/>
> URL: [http://localhost:34861/workspace/logs](http://localhost:34861/workspace/logs)

Bifrost to wydajna brama AI udostępniająca API zgodne z OpenAI dla lokalnych i zdalnych dostawców modeli. Harbor uruchamia ją z trwałą konfiguracją opartą na SQLite i może automatycznie konfigurować backendy Harbor, takie jak Ollama, llama.cpp, Docker Model Runner, MLX i oMLX.

![Panel Bifrost w Harbor](./harbor-bifrost.png)

## Uruchamianie

```bash
harbor pull bifrost
harbor up bifrost --open
```

Panel działa bez wymaganych danych uwierzytelniających. Dostawców chmurowych skonfigurujesz w interfejsie; możesz też uruchomić Bifrost razem z backendami Harbor, aby automatycznie je zarejestrować:

```bash
harbor up bifrost ollama
harbor up bifrost llamacpp
harbor up bifrost ollama llamacpp
```

Endpoint zgodny z OpenAI jest dostępny pod adresem:

```bash
http://localhost:34861/v1
```

W sieci Harbor użyj:

```bash
http://bifrost:8080/v1
```

## Integracje Harbor

### Ollama

Gdy `bifrost` i `ollama` są uruchomione razem, Harbor uruchamia jednorazowy kontener bootstrapujący, który rejestruje dostawcę `ollama` wskazującego na `${HARBOR_OLLAMA_INTERNAL_URL}`.

Modele Bifrost wywołuj z prefiksem dostawcy, na przykład:

```bash
curl http://localhost:34861/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer sk-bifrost' \
  -d '{
    "model": "ollama/qwen3.5:4b",
    "messages": [{"role": "user", "content": "hello"}]
  }'
```

### llama.cpp

Gdy `bifrost` i `llamacpp` są uruchomione razem, Harbor rejestruje niestandardowego dostawcę zgodnego z OpenAI o nazwie `llamacpp`, wskazującego na `http://llamacpp:8080`.

```bash
harbor up llamacpp bifrost
```

Domyślnie podczas bootstrapu Harbor wykrywa identyfikatory modeli z `http://llamacpp:8080/v1/models` i rejestruje je w Bifrost. Następnie wywołuj modele przez Bifrost z prefiksem dostawcy `llamacpp/`, na przykład `llamacpp/Qwen3-0.6B-Q4_K_M.gguf`.

### Docker Model Runner

Gdy `bifrost` i `dmr` są uruchomione razem, Harbor rejestruje niestandardowego dostawcę zgodnego z OpenAI, wskazującego na `http://dmr:8080` i skonfigurowanego zmiennymi `HARBOR_BIFROST_DMR_*`.

```bash
harbor up dmr bifrost
```

Modele wywołuj przez Bifrost z prefiksem `dmr/`, na przykład `dmr/ai/smollm2`.

### MLX

Gdy `bifrost` i `mlx` są uruchomione razem, Harbor rejestruje MLX pod adresem `http://mlx:8080`, używając zmiennych `HARBOR_BIFROST_MLX_*`.

```bash
harbor up mlx bifrost
```

Modele wywołuj przez Bifrost z prefiksem `mlx/`, na przykład `mlx/mlx-community/Qwen3.5-4B-4bit`.

### oMLX

Gdy `bifrost` i `omlx` są uruchomione razem, Harbor rejestruje oMLX pod adresem `http://omlx:8080`, używając zmiennych `HARBOR_BIFROST_OMLX_*`.

```bash
harbor up omlx bifrost
```

Modele wywołuj przez Bifrost z prefiksem `omlx/`, na przykład `omlx/Qwen3.5-4B-4bit`.

### Open WebUI

```bash
harbor up bifrost webui
```

Dodaje to Bifrost do Open WebUI jako backend zgodny z OpenAI.

### Harbor Boost

```bash
harbor up bifrost boost
```

Rejestruje to Bifrost jako nazwaną usługę API dla Harbor Boost.

## Konfiguracja

### Zmienne środowiskowe

Poniższe opcje można ustawić za pomocą [`harbor config`](./3.-Harbor-CLI-Reference.md#harbor-config):

```bash
HARBOR_BIFROST_HOST_PORT              # Port hosta dla interfejsu/API Bifrost
HARBOR_BIFROST_IMAGE                  # Obraz kontenera
HARBOR_BIFROST_VERSION                # Tag obrazu kontenera
HARBOR_BIFROST_WORKSPACE              # Trwały obszar roboczy Harbor
HARBOR_BIFROST_APP_PORT               # Wewnętrzny port HTTP Bifrost
HARBOR_BIFROST_INTERNAL_URL           # Wewnętrzny URL Harbor dla innych usług
HARBOR_BIFROST_OPEN_URL               # URL przeglądarki otwierany przez `harbor open bifrost`
HARBOR_BIFROST_API_KEY                # Zastępczy token bearer używany przez klientów Harbor
HARBOR_BIFROST_LOG_LEVEL              # Poziom logowania Bifrost
HARBOR_BIFROST_LOG_STYLE              # Format logów Bifrost
HARBOR_BIFROST_BOOTSTRAP_IMAGE        # Pomocniczy obraz kontenera bootstrapującego dostawców
HARBOR_BIFROST_BOOTSTRAP_VERSION      # Tag pomocniczego obrazu kontenera bootstrapującego dostawców
HARBOR_BIFROST_OLLAMA_MODELS          # Lista dozwolonych modeli dla automatycznie rejestrowanego klucza Ollama
HARBOR_BIFROST_LLAMACPP_BASE_URL      # Wewnętrzny bazowy URL llama.cpp rejestrowany w Bifrost
HARBOR_BIFROST_LLAMACPP_API_KEY       # Klucz API wysyłany z Bifrost do llama.cpp
HARBOR_BIFROST_LLAMACPP_MODELS        # Lista dozwolonych modeli llama.cpp; `*` automatycznie wykrywa modele z /v1/models
HARBOR_BIFROST_DMR_BASE_URL           # Wewnętrzny bazowy URL Docker Model Runner rejestrowany w Bifrost
HARBOR_BIFROST_DMR_API_KEY            # Klucz API wysyłany z Bifrost do DMR
HARBOR_BIFROST_DMR_MODELS             # Lista dozwolonych modeli DMR; `*` automatycznie wykrywa modele z /v1/models
HARBOR_BIFROST_MLX_BASE_URL           # Wewnętrzny bazowy URL MLX rejestrowany w Bifrost
HARBOR_BIFROST_MLX_API_KEY            # Klucz API wysyłany z Bifrost do MLX
HARBOR_BIFROST_MLX_MODELS             # Lista dozwolonych modeli MLX; `*` automatycznie wykrywa modele z /v1/models
HARBOR_BIFROST_OMLX_BASE_URL          # Wewnętrzny bazowy URL oMLX rejestrowany w Bifrost
HARBOR_BIFROST_OMLX_API_KEY           # Klucz API wysyłany z Bifrost do oMLX
HARBOR_BIFROST_OMLX_MODELS            # Lista dozwolonych modeli oMLX; `*` automatycznie wykrywa modele z /v1/models
```

Harbor przekazuje również współdzielone klucze dostawców, takie jak `HARBOR_OPENAI_KEY`, `HARBOR_ANTHROPIC_KEY`, `HARBOR_MISTRAL_KEY`, `HARBOR_GROQ_KEY` i `HARBOR_COHERE_KEY`, do kontenera Bifrost, używając nazw zmiennych środowiskowych wymaganych w przykładach Bifrost.

### Wolumeny

```bash
${HARBOR_BIFROST_WORKSPACE}:/app/data
```

Bifrost przechowuje w `/app/data` bazę konfiguracji SQLite, bazę logów żądań oraz opcjonalny plik `config.json`.

## Rozwiązywanie problemów

```bash
harbor logs bifrost
```

Sprawdź endpoint zdrowia:

```bash
curl http://localhost:34861/health
```

Jeśli backend nie został zarejestrowany, sprawdź logi pobocznych kontenerów bootstrapujących:

```bash
docker logs harbor.bifrost-ollama-bootstrap
docker logs harbor.bifrost-llamacpp-bootstrap
docker logs harbor.bifrost-dmr-bootstrap
docker logs harbor.bifrost-mlx-bootstrap
docker logs harbor.bifrost-omlx-bootstrap
```

Jeśli Bifrost został już skonfigurowany ręcznie, kontenery bootstrapujące aktualizują identyfikatory dostawców i kluczy zarządzanych przez Harbor, zamiast zastępować pozostałych dostawców.
